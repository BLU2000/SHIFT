# Facade ID

**Local SegFormer WWR pilot:** see [wwr-segformer/README.md](wwr-segformer/README.md). The supplied research checkpoint is installed locally and a 20-photo pilot is available in `wwr-segformer/results/pilot/review.html`. HTML 17 supports **Import SegFormer WWR** for separate estimated ratios, mask previews and verification status; manual survey tags are preserved.

**HTML 17 map bulk tagging:** open Analysis and choose Map or Both. Above the map, choose **Select polygon**, click its corners, then **Finish selection**. Points inside or on the boundary are selected, including every photo at a shared location. The selection applies only to photos matching the current analysis filters; photos without coordinates are excluded. Choose a whole-facade/context attribute or an existing sorted category, choose its value, inspect the change count/preview and Apply. Fill unanswered only is the default; replacement and adding to multi-selection answers are explicit modes. Changes autosave and reopen affected profiles. **Undo last change** restores the edited attribute while protecting later edits. Polygon selections are temporary; applied tags are included in normal HTML/JSON saves.

Open **Facade-ID.html** in a modern browser. It contains the entire English application and all 204 photographs from `images/images all/New Photos`, replacing the previous collection. No server, account, internet connection, or photo import is required. Original photos are preserved; embedded JPEG copies are resized to a maximum of 1600 pixels for portability, respecting EXIF orientation. A new collection ID separates this batch from previous browser answers; `Facade-ID-previous-batch.html` retains access to the previous collection and its browser state.

Urban context includes multiple-selection **Ground-floor use**: Gastronomy, Retail, Groceries, Residential, Office / services, Community / public use, Parking, Vacant, Other, or Unknown.

The interface uses Yves/Klein blue (#002FA7), white, and black. The preferred font is DIN 2014, with Bahnschrift and system sans-serif fallbacks. DIN 2014 is not bundled; it must be installed on the user's computer or supplied as a licensed webfont to display exactly on every computer. Photograph colors are preserved; the live map uses a neutral Positron style.

**Add photos** in the sidebar accepts multiple new photographs. JPEG, PNG, WebP, GIF and AVIF are decoded locally; HEIC/HEIF works only if the browser supports it, otherwise convert to JPEG first. Photos are resized to a maximum of 1600 pixels and embedded as JPEG. Uploaded photos persist in browser storage and are included in saved HTML, including when merging participant copies. The same original file has a stable SHA-256 ID, so uploading it twice skips duplicates. Use the map to place newly uploaded photos; GPS extraction from new uploads is not implemented.

**Delete photo** below the photograph removes that image and its answers from this collection after confirmation. Original disk files are untouched. Deletions persist in browser storage and saved HTML, and older merged copies cannot restore locally deleted uploaded photos. **Undo last deletion** in the sidebar restores the last image and its answers until the app is reloaded or closed. Other participants' deletions are not automatically applied when merging their files. Deliberately adding a previously deleted upload makes it available again.

Every selected façade type except Punched-window façade (Lochfassade) asks for threshold depth and enclosure directly. There is no separate threshold yes/no question. Enclosure uses Low (mostly open), Medium (partly enclosed), High (mostly enclosed), or Unknown. Depth includes Not applicable. Previous fractional opening ratios are preserved in old data but are not silently converted into the new enclosure categories. The radar comparison uses enclosure rather than opening ratio. The app background is Yves blue, with white form panels.

The optional **live location map** requires internet. In Location, click **Open live map**, then click the street map or drag the pin to place the photograph. **Pin map center** provides another way to choose a location. You can clear the pin, restore the photo's original GPS, or edit coordinates directly. All changes save automatically and are included in HTML/JSON exports and merges. The OpenStreetMap link opens the selected position in a separate tab.

Live maps use [OpenFreeMap](https://openfreemap.org/) with OpenStreetMap data and the open-source MapLibre GL JS library; no API key is needed. MapLibre and its CSS are embedded in the standalone HTML. Only map styles and tiles load online, when you open the map. If the map service or WebGL is unavailable, the coordinate fields and external OpenStreetMap link remain usable. Standard browser requests for the viewed map area are sent to the map provider; photos and answers remain local. Map attribution is displayed on the live map.

## Working and sharing

**Sort into categories** in the sidebar opens a visual sorting canvas. One unsorted photograph sits in the center, with numbered category folders around it. Drag it to an existing folder or the New category target to assign its building-type label and automatically show the next photograph. Clicking a folder is an alternative to dragging. Folder thumbnails preview existing members; hovering or focusing a folder shows its full contents below. Select a member thumbnail to move it to another category. Skip defers an image for the current session; Show unsorted brings skipped images back. Undo restores the last assignment. Up to six existing folders appear per circle, with page arrows for additional folders. There is no manual number field in the survey. Categories remain separate from detailed façade descriptions, preserve their completion state, and persist in browser autosave, HTML downloads, and record merging. Original image files are never moved into physical directories.

- Answer Location → Urban context → Divide façade → Describe types → Review.
- Location and contributor information are optional. All classification questions are required before marking a photograph complete.
- Answers save automatically to IndexedDB in the same browser. Browser storage is local to the browser/profile and can be cleared. Some private browsing environments restrict persistence.
- **Save** asks for your initials (for example BU), then downloads a self-contained copy such as `Facade-ID_BU_v001.html`. The next save becomes `v002`. Initials, revision, and save time are stored inside the HTML, and the sequence continues when reopening a saved copy. The browser also remembers the latest revision for this collection. Each participant's independent copy can have its own sequence; this is not a central version-control system. Canceling does not increment the revision.
- Use Save before sharing or moving computers. It downloads a new file rather than silently overwriting the original. Allow the download and verify the downloaded copy exists; browsers cannot confirm that a download was actually kept on disk.
- **Merge files** in the sidebar accepts HTML files and legacy JSON answers, including multiple files. Stable photograph IDs match records. Conflicting profiles require an explicit choice; they are never silently overwritten. Resolve conflicts before handing off the final collection.
- Each participant should work in their own browser/profile. Multiple copies of this collection opened in the same browser share its saved work. Avoid editing this collection in multiple tabs simultaneously.

## Analysis

Canvas charts now include **Facade type area shares**. Select this chart type and group by Orientation (default), or another whole-facade attribute. Each stacked bar shows the mean of each section type's share of the entire facade area (`types[].share`), rather than the fraction of photographs containing the type. All valid facades receive equal weight because total facade areas in square metres are not recorded. Repeated sections of the same type are combined, shares are normalized to sum to 100%, and incomplete multi-type shares exclude that facade with a reported count. A single known type can omit its share and contributes 100%. All sections of each filtered facade are retained; missing group labels appear as Unanswered. A table lists the percentages and valid/excluded counts, and selecting a segment opens contributing facade profiles. Run `node facade-area-share-checks.cjs` for calculation checks.

Numeric **Bar chart** graphs on the analysis canvas now show coverage around the category nearest the observed mean, replacing the Gaussian/standard-deviation overlay. The anchor category, one neighbouring category on each side, and two on each side are highlighted. The table reports actual counts and percentages of all valid values, with Inspect buttons for their profiles. Storeys use one-storey steps; whole-facade WWR uses the existing 5-percentage-point scale; section ratios use their defined fractional categories. Empty categories count as steps, ranges stop at scale endpoints, and exact ties select the higher category. WWR means use unrounded saved measurements, while membership uses the nearest displayed category. Categorical bars remain unchanged. Each whole-facade metric counts each image once; section metrics count matching sections. Run `node category-coverage-checks.cjs` for counting checks; browser checks exercise the canvas iframe.

**Primary façade type** now follows the threshold when one is present, even if punched openings occupy more area. If several threshold types occur, their shares are summed by type and the largest threshold type wins; punched-opening shares do not compete. Tied largest types, missing shares between competing thresholds, and incomplete section classifications remain Unknown with an explanation. A known façade with no threshold becomes Punched-window façade. All threshold labels remain separately available. Section details take precedence over older manual whole-facade tags; original replaced tags are retained in `context.wholeFacadeOriginal`. The derived primary label updates in tagging, filters, clustering, combination counts and normal saves. Mixed is removed from primary-type choices; composition remains a separate attribute.

The combination street background uses OpenFreeMap Positron through the embedded MapLibre–Leaflet adapter, matching the app's existing provider. It does not request standard `tile.openstreetmap.org` raster tiles, which can reject standalone `file://` pages without a website referrer. Street detail requires internet and WebGL; offline outlines and Leaflet markers remain usable if the background cannot initialize.

The combination map now has a large full-width interactive viewport with zoom controls, mouse-wheel zoom, drag-to-pan and Show all locations. OpenStreetMap street tiles are enabled by default (internet required); toggle Street background off for embedded offline country outlines. A distinct palette is assigned across all observed combinations for the selected attributes, preserving colours when analysis filters hide groups. Colours are not recycled within a result; bar, table and map colours agree. For many combinations, use row numbers alongside colours.

Category combinations use matching colours in the bar chart, table swatches and an embedded offline location map. Select bars or markers to inspect members. Shared coordinates show count markers with coloured segments for every combination present; selecting a segment lists its located members. Missing/invalid coordinates are reported separately and never removed from frequency counts. The map uses embedded geo-countries outlines with a coordinate grid; close-up views do not contain street detail.

**Category combinations** in the header opens a direct frequency analysis in the main standalone file. Select attributes to count observed combinations, with one contribution per photograph/facade. Multi-label sets remain intact (Balcony + Loggia is one category); no cross-products are invented. Choose exact storey counts or three-/five-storey bands, optionally apply current analysis filters, and include or exclude incomplete selected answers. The table shows counts, percentages, matching members and a total; a bar chart shows the twelve most frequent rows. Select View to inspect matching photos or open their profiles. CSV exports include counts, percentages, denominator and photo IDs. Settings persist in normal HTML saves. Run `node facade-combinations-checks.cjs` for counting checks.

The clustering **Cluster shares** pie chart shows each cluster's count and percentage of eligible clustered facades. Each facade counts once. Missing-data exclusions and facades outside enabled analysis filters are outside the denominator; these exclusions are stated beside the chart. Pie colours match the radar, plot and cluster summaries.

**Whole-facade thresholds** are derived automatically from existing whole-facade and section-type tags, shown in the tagging/profile interface, and exposed as **Whole facade: has threshold** and **Whole facade: threshold types** in analysis filters, charts and clustering. Any positive threshold type tags the whole facade; all observed types are retained as multiple labels. Punched openings alone yield No / None. Zero-share sections are ignored. Incomplete classifications retain Unknown rather than inventing a type; known positive thresholds still yield Yes. These are live derived attributes, so edits and merges cannot leave stale copied tags behind.

Clustering also offers **Starting configurations** (1–50, default 20) and a reproducible random seed. Each k uses distinct sets of initial representative facades and retains the lowest final total distance; ties keep the earliest trial. A previous-k continuation is included to keep elbow costs non-increasing. The selected-k results show each start's initial and final cost, mean distance, initial representatives, and winning start. Additional starts can improve the solution but do not guarantee a global optimum. When there are fewer possible initial sets than requested, fewer trials are reported.

**Cluster facades** in the header opens whole-facade clustering in `Facade-ID.html` and `Facade ID/Facade-ID_Main.html`. Choose attributes, weights, an elbow maximum (2–10), and final cluster count. K-medoids compares normalized numeric values, categorical/multi-label overlap, and area-weighted type-label distributions. Type shares use the whole facade as their denominator and are rescaled to sum to one; multiple types require known shares. Missing selected attributes exclude a facade and are listed. Current analysis filters can select the cohort; all types of each included facade contribute to its profile.

The proposed threshold score (punched = 0, French balcony = 1, bay window = 2, loggia = 3, semi-loggia = 4, balcony = 5) is an analytical ordinal scale, not physical projection depth. It is area-weighted and divided by 5; select it instead of threshold-type shares to avoid double counting. Results include an elbow curve, silhouette scores, radar profiles, representatives, member previews and CSV assignments. One/two/three numeric attributes use a strip/scatter/rotatable 3D view. Categorical or higher-dimensional inputs use a labelled 2D PCA visualization; clustering still uses full attribute distances. Radar category axes show prevalence, not category rankings. Storey counts use cohort min–max scaling; bounded numeric measures use fixed 0–1 scales. Settings persist in normal saves; clustering never replaces survey labels or sorted categories. Run `node facade-clustering-checks.cjs` for algorithm checks and `node check-facade-clustering.cjs` for isolated Chrome UI checks. After editing the clustering source, run `node integrate-facade-clustering.cjs` to refresh both standalone files.

Analysis has shared attribute filters and Gallery / Map / Both views. Gallery cards show large façade images, filenames, category numbers, façade types, completion status, and missing-coordinate indicators. Select a card for a larger preview with its existing tags, Previous/Next navigation (also arrow keys), and Edit tags. Photos without coordinates still appear in the gallery. Gallery-only mode does not initialize or request the live map. The display preference and filters persist in browser storage and saved HTML. Temporary preview dialogs are excluded from exports.

**Add graph** creates an independent X/Y attribute comparison. Add multiple graphs, choose a different pair of survey attributes in each, or remove graphs individually. They use the same filters as the map and gallery; type-specific filters restrict observations to the matching individual types. Ratios use numeric positions, while categorical attributes use labelled category positions. Missing, Unknown, and Not applicable answers are excluded. Each type is an observation; multiple-selection answers can contribute to multiple points and photo-level attributes repeat across a photo's types. Coincident observations form counted bubbles. Select a bubble to list and preview its photos. Graph configurations persist in browser storage and saved HTML, and Clear all resets filters without removing graphs.

Each graph also offers **Bar chart** or **Pie chart** with a single attribute selector. Distributions count type attributes once per matching façade type and context/category/status attributes once per photo. Missing answers are excluded; explicit Unknown and Not applicable answers are shown as categories. Multi-selection attributes count each selection; pie percentages use the total number of selections as their denominator, stated below the chart. Select bars, pie slices, or legend entries to see contributing photos. Chart type and attribute are saved with the HTML, and existing X/Y graphs remain compatible.

**Color graph + map** links one graph's attribute colors to the location markers. Choose Gradient (light-to-dark blue following numeric values or the displayed category order) or Category colors. X/Y graphs let you choose X or Y as the color attribute; bar/pie charts use their selected attribute. Only one graph controls map colors at a time. Shared-coordinate markers and multi-valued façades show split colors rather than an invented average. Missing/Unknown/Not applicable values are neutral gray. Legends appear beside the graph and map. These are attribute colors, not a spatial-density heatmap. Color settings are included in autosave and HTML saves.

Add filter rows for any survey attribute, sorted category number, tagging status, or presence of coordinates. Different attributes combine with AND; repeated choices for one attribute combine with OR. For heterogeneous façades, all type-specific filters must match the same individual type. Multiple-selection attributes match any selected use/element. Photo-name search is also available. Existing chart settings remain in older saved data, but charts and the matrix are no longer shown.

The Geographic overview displays only the matching located photos on an interactive OpenFreeMap street map. Zoom with the mouse wheel, touch gestures, or +/− controls; drag to pan. Show all photos fits the current matching set. Select a marker to see photo previews and open a profile. Photos with identical coordinates share a counted marker. Matching photos without coordinates remain in the result list and are counted separately. Clear all restores the full collection. The live basemap requires internet; an offline coordinate overview is available if map loading fails.

Photo region annotations are not implemented. Both the collection overview and each photo's Location step have live street maps.

GPS metadata is available for 187 of the 204 replacement photos. EXIF and XMP were checked. These coordinates prefill the Location step and appear on the geographic overview even before classification. Existing manually entered coordinates take priority. The 17 photos IMG_4591 through IMG_4607 have no GPS metadata and need manual pins. `new-photo-locations.json` records the extraction results. Photo GPS describes the camera position, rather than an exact building address. No reverse geocoding or external upload is performed.

## Source and rebuilding

`index.html` is the editable application template. `prepare_collection.ps1` produces the standalone deliverable with the existing JPEG copies. Run it again after changing the template:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File prepare_collection.ps1
```

`prepare_collection.ps1` resizes JPEGs from the replacement folder into `images/browser-new-photos` and embeds exactly the source folder's current inventory. It preserves originals. `convert_photos.py` was used only for the previous HEIC collection.

`extract_new_photo_locations.py` reads JPEG EXIF/XMP GPS locally and writes `new-photo-locations.json`; run it before preparation when changing the photo batch. It reuses the TIFF GPS parser in `extract_locations.py` (which loads the locally installed GIMP library). The earlier `photo-locations.json` report belongs to the previous HEIC collection.

`browser_checks.py` prepares an offline browser smoke test from the template, covering required fields, multiple selection, conditional types, autosave, merging, completion, analysis, and HTML export. It uses only the Python standard library.
